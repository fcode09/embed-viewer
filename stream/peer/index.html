How this pilot works

The server publishes static files and a trusted JSON hash manifest, and coordinates anonymous peers. It never downloads, stores, or relays the MP4. Video bytes travel from Drive or another browser to this browser. A Service Worker scoped to /stream/peer/ serves verified 1 MiB blocks to the native player, without waiting for a complete video download. Missing peer blocks fall back to Drive; a key is required for that fallback.

All source blocks must match the operator-published SHA-256 hashes. The operator must regenerate the manifest if Drive changes. No independent whole-file preload runs. The native browser still decides how much media to buffer and may request many blocks. Statistics count complete useful blocks, excluding protocol overhead, aborted traffic, and signalling. Playback controls and buffering remain browser-dependent.

Closing stops this tab's transfers/sharing and clears its key, but keeps saved blocks. Reloading reuses this origin/profile's saved blocks. Separate profiles have separate caches. Clearing removes this origin's pilot video cache only; another open tab may write again.
